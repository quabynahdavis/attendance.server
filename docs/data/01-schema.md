# Schema

The database is SQLite, as specified in `OVERVIEW.md`. It has six tables and no others. Column types are SQLite types: `TEXT`, `BLOB`, and `INTEGER`. Byte lengths in this contract are exact. The HTTP layer rejects a wrong length before insert, as specified in `../http/01-routes.md`. `BLOB` columns store the raw bytes, not the base64 form used in JSON. Booleans are integers `0` and `1`. Timestamps are unix seconds stored in `INTEGER`. Foreign keys are enabled on the connection. Primary keys and foreign keys are unchanged.

The server verifies signatures and does not store them. `confidence` is not a column. Handlers derive it from `chirp_ok` when they write a response: `high` when `chirp_ok` is `1`, and `low` when `chirp_ok` is `0`.

## students

| Column | Type | Rule |
| --- | --- | --- |
| `index_number` | TEXT | Primary key |
| `public_key` | BLOB | NOT NULL. 32-byte Ed25519 public key |
| `display_name` | TEXT | NULL allowed. NULL when registration omits `displayName` |

The first stored `public_key` owns that `index_number`. A repeat registration with the same key does not change the row. A different key is rejected by `POST /students`.

## lecturers

| Column | Type | Rule |
| --- | --- | --- |
| `id` | BLOB | Primary key. 16 bytes, generated by the server |
| `public_key` | BLOB | NOT NULL. 32-byte Ed25519 public key |
| `display_name` | TEXT | NOT NULL |

`POST /lecturers` draws the 16-byte `id`.

## courses

| Column | Type | Rule |
| --- | --- | --- |
| `id` | BLOB | Primary key. 16 bytes, generated by the server |
| `code` | TEXT | NOT NULL. Unique |
| `title` | TEXT | NOT NULL |
| `lecturer_id` | BLOB | NOT NULL. 16 bytes. References `lecturers(id)` |

`code` is unique across courses. `POST /courses` draws the 16-byte `id`. `lecturer_id` is the lecturer who teaches the course.

## roster

| Column | Type | Rule |
| --- | --- | --- |
| `course_id` | BLOB | NOT NULL. 16 bytes. Part of the primary key |
| `index_number` | TEXT | NOT NULL. Part of the primary key. References `students(index_number)` |

Primary key: `(course_id, index_number)`.

`index_number` references `students`. A student must already exist before a roster row is written. The HTTP routes also require the course to exist before a roster row is written.

## lectures

| Column | Type | Rule |
| --- | --- | --- |
| `id` | BLOB | Primary key. 16 bytes, generated by the server |
| `course_id` | BLOB | NOT NULL. 16 bytes. References `courses(id)` |
| `starts_at` | INTEGER | NOT NULL. Unix seconds |
| `ends_at` | INTEGER | NULL allowed. Unix seconds. NULL means the lecture is still open |

`POST /courses/{id}/lectures` draws the 16-byte `id` and stores `ends_at` as NULL. `POST /lectures/{id}/end` sets `ends_at` to the server time. A lecture with `ends_at` NULL is open. A lecture with `ends_at` set has ended.

## attendance

| Column | Type | Rule |
| --- | --- | --- |
| `index_number` | TEXT | NOT NULL. Part of the primary key |
| `lecture_id` | BLOB | NOT NULL. 16 bytes. Part of the primary key |
| `nonce` | BLOB | NOT NULL. 8 bytes |
| `issued_at` | INTEGER | NOT NULL. Unix seconds. On a sensor row, the uint32 covered by the lecturer signature |
| `rssi` | INTEGER | NOT NULL |
| `chirp_ok` | INTEGER | NOT NULL. `1` or `0` |
| `source` | TEXT | NOT NULL. Check constraint: `source` is `sensor` or `manual` |
| `created_at` | INTEGER | NOT NULL. Unix seconds, set by the server on insert |

Primary key: `(index_number, lecture_id)`.

One student has one row per lecture. Sensor insert, the conflict response, and the `chirp_ok` upgrade from `0` to `1` are defined on `POST /lectures/{id}/attendance` in `../http/01-routes.md`. A conflict must not change `chirp_ok` from `1` to `0`. Manual insert is defined on `POST /lectures/{id}/attendance/manual`. A manual insert stores `source` `manual`, `chirp_ok` `0`, `rssi` 0, an 8-byte nonce of zeros, and `issued_at` equal to the server time.

There is no separate nonce table. A nonce is a column on the attendance row. For a sensor row, freshness is the lecturer signature over `issued_at` plus the server check that `issued_at` is within 20 seconds of server time. Those rules are in `../crypto/01-signatures.md` and `../http/01-routes.md`.

`rssi` and `chirp_ok` are client assertions on a sensor submission. They are not proof of location.
